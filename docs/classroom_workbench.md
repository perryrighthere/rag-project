# 课堂工作台使用说明

## 知识库管理

在工作台打开“知识库管理”，选择知识库后可以查看名称、说明、绑定模型、切分配置及库内文档。支持修改名称和说明、按文件名搜索、显示已删除文档、查看解析内容，以及跳转上传与入库页面。各页面共享知识库选择。

“删除知识库”会先显示确认提示及文档数量。确认后，在数据库事务中删除知识库、文档、片段和处理任务；历史实验报告保留快照。存在 pending/running 任务时拒绝删除。此操作不可撤销。MinIO 对象与 Milvus 残留向量暂不物理清理，检索通过数据库状态排除这些文档。

接口：`DELETE /knowledge-bases/{kb_id}` 成功返回 `deleted: true`；不存在返回404；存在活动任务返回409。名称与说明通过已有 `PATCH /knowledge-bases/{kb_id}` 修改。不需要新增数据库字段或安装 npm 包。

## 准备

使用 Python 3.12 和仓库 `requirements.txt`。最轻量的预览方式：

```bash
DATABASE_URL='sqlite+pysqlite:///./classroom.db' PYTHONPATH=src .venv/bin/uvicorn rag_project.main:app --reload
```

打开 `http://127.0.0.1:8000/workbench/`。页面、数据和报告均由同一 FastAPI 服务提供，无 npm 依赖。数据库首次启动自动创建缺失表，包括新的 `experiment_reports` 表。

| 操作 | 所需服务 |
| --- | --- |
| 查看固定资料、切分预览、导入副本、查看历史报告 | 应用和数据库 |
| 索引、真实向量检索 | 再加 Embedding API 与 Milvus |
| 重排序 | 可选 Rerank API；无配置时保持召回顺序 |
| 生成答案 | 再加 Chat API |
| 普通 PDF 等文件解析 | 使用原有 MinerU、MinIO 流程 |

Compose 启动方式保持不变；它不会提供模型 API 或 MinerU。工作台不读取或展示 API Key。

## 固定数据

`src/rag_project/teaching/dataset.json` 包含原创虚构文档，不含真实个人信息。数据版本 `1.0.0`，导入时记录整个数据文件的 SHA-256。

- 财务处2024版差旅办法：住宿350元，30天内提交。
- 财务处2025版差旅办法：普通教职工住宿450元，15天内提交，包含表格和金额计算。
- 科研处差旅补充规定：项目审批、预算审批，引用财务处标准。
- 学生处活动报销指南：每场物资800元，10天内提交。
- 图书馆服务规则：借阅、研讨室、教学周开放时间；未提供具体节假日时间。

问题集包含单文档、跨文档、版本冲突、部门过滤、计算和无答案问题。`expected_document_ids` 是固定数据中的文档标识，不是运行时随机生成的数据库文档 ID；报告文档的 `parse_options.fixture_id` 可用于对应。参考答案不属于检索语料，只在页面和报告中用于人工核验。

## 一次实验

1. 在“资料与切分”选择文档，设置长度与重叠，点击预览。
2. 点击“创建教学知识库副本”，保存当前切分配置与独立文档。重复导入会创建新副本，不覆盖已有实验。
3. 点击“索引 / 重建全部有效文档”。界面依次提交任务并显示进度；刷新页面不会取消已提交的后台任务，但尚未提交的后续文档不会继续索引。
4. 选择问题和过滤条件，运行仅检索或问答。需要额外模型调用的操作只在点击后执行。
5. 查看实际过滤表达式、初始召回、最终排序、完整片段、实际上下文与提示词。单次生成调用一次 Chat；有证据时四角色模式顺序调用四次；无证据时内置多角色模式直接返回无法确认。
6. 在报告历史查看快照、下载 Markdown 或访问完整 JSON。可在报告中填写本次观察，再进行下一组对照。

报告保存在服务端数据库，不是浏览器 localStorage。删除数据库或删除 Compose 数据卷会丢失报告，刷新页面和正常重启不会。实验在请求内执行；强制终止进程可能留下 `running` 报告，需要重新运行，不支持断点恢复。时间包含实际服务等待，不能等同于纯模型推理时间。

## 上传自己的文件

1. 打开“上传与入库”。选择已有知识库，或展开“新建空白知识库”，填写名称并创建。默认 schema 为 `{"fields":[]}`，此时无需填写 metadata。
2. 若要按年份等字段过滤，可在创建时设置 schema，例如 `{"fields":[{"name":"year","type":"int","required":true,"filterable":true}]}`。上传表单会按 schema 自动生成输入字段；必填字段会标记，布尔值用下拉选择，字符串数组用 JSON 数组填写。
3. 选择一个或多个本地文件。本批文件共用同一份 metadata，不同属性的文件请分批上传。具体可解析格式由部署的 MinerU 服务决定。
4. 选择“仅上传”可先保存文件，稍后在列表中选择“仅解析”或“解析并入库”；默认“上传并完整入库”会先保存本批文件，再依次启动入库任务。
5. 任务执行时会显示实际阶段、task_id 和可用的 MinerU parser_task_id。失败后原文件仍在，不需要重复上传；使用已有文档的操作按钮重试。若某个文件处理失败，其余已上传文件可以在列表中继续处理。
6. 点击“查看内容”查看解析 Markdown 与数据库中的索引片段。索引完成后点击“前往检索与问答”，输入自定义问题，运行并自动保存报告。

“索引 / 重建全部有效文档”只处理有解析结果且未删除的文档；新上传文件需先解析。活动任务期间不可重复处理或删除同一文档。工作台记住当前知识库；刷新后点击“刷新文档与任务”或“继续查看进度”即可查询服务端状态。刷新页面会中断浏览器中尚未提交的批次操作，已经提交的后台任务仍由服务进程执行；应用重启仍遵循原有的任务失败处理机制，不支持续跑。

仅上传需要应用和数据库；解析需要 MinerU 和 MinIO；索引需要 Embedding API 和 Milvus。上传/索引任务本身不是问答实验报告，可在文档列表查看最新任务；所有历史任务可通过 `GET /knowledge-bases/{kb_id}/tasks` 查询。

## 三组对照

### 年份过滤

对 Q1 先使用 `{}`，再使用 `{"year": 2025, "department": "财务处"}`。观察是否同时召回旧版与新版，答案是否采用正确版本。两次报告比较证据，不仅比较文字表达。

### 切分与跨文档召回

分别创建 `chunk_size=100, chunk_overlap=10` 和 `chunk_size=800, chunk_overlap=120` 的副本。均完成索引后运行 Q3，固定模型、过滤条件和 top_k/top_n。检查是否同时包含科研审批与财务标准的证据。切分器按字符计数，标题会重新拼回正文。

### 重排序与上下文数量

对相同知识库和问题切换 rerank 开关，或仅改变 top_n。比较目标文档是否进入最终上下文，以及答案是否遗漏条件。未配置重排服务时，开启开关不会产生重排效果；报告 `rerank_status` 会记录 disabled、not_configured、applied 或 fallback。

Q6/Q7 用来检查拒答：召回到相近文字也不证明答案存在。不对无答案问题机械计算“相关片段命中率”。报告不自动打正确性分数，也不将生成的 `citations` 当作已验证证据。

## 正确性约束

如果 MinerU 日志成功，但工作台显示“解析成功 · 入库失败”，先查看任务中的失败阶段。解析文本已经保存，可以点击“查看内容”；修复索引配置后点击“重试索引（无需重新解析）”。无需重新上传或再次调用 MinerU。

若错误包含 `Milvus collection embedding model/dimension is different or unverified`，说明现有集合的模型标记不匹配或无法验证。将 `.env` 的 `MILVUS_COLLECTION` 设置为未使用的新名称（例如 `rag_chunks_classroom_v2`），保持同一 Embedding 模型与维度，然后重新创建应用容器以加载配置。切换集合影响整个应用：需要继续检索的其他文档也要重建索引；旧集合保留。不要只给旧集合补模型标签来绕过校验。

- 删除或索引失败的文档不会被新检索选中。活动任务期间禁止重复提交处理或删除；晚到的写入不能恢复删除状态。
- 知识库绑定模型名与维度；collection 同时校验模型标识与实际向量维度。模型不一致时，在删除旧向量前拒绝索引。
- 旧 collection 没有模型标识，需要使用新 collection 重建。更换模型要创建新的知识库和 collection，所有服务进程应使用同一配置。
- metadata 不允许覆盖系统字段（例如 kb_id、text、embedding）；调用方不能提交原始 Milvus 表达式。
- 重建仍是删除旧向量后写入新向量，尚无跨数据库与 Milvus 的原子切换；失败文档会退出检索，重新索引后才能恢复。

## 教学接口

| 接口 | 用途 |
| --- | --- |
| `GET /teaching/dataset` | 固定文档、问题、版本和校验和 |
| `POST /teaching/preview` | `document_id`（固定数据ID）和可选 `chunking_config` |
| `POST /teaching/dataset/import` | 按可选 `chunking_config` 创建新副本 |
| `GET /knowledge-bases/{kb_id}/documents` | 查看文档及索引状态 |
| `GET /knowledge-bases/{kb_id}/tasks` | 查看该知识库的处理任务（最新在前） |
| `POST /teaching/experiments` | 运行并自动保存实验，返回报告（含成功或失败状态） |
| `GET /teaching/experiments` | 最近100条报告摘要 |
| `GET /teaching/experiments/{id}` | 完整报告 JSON |
| `GET /teaching/experiments/{id}/markdown` | 下载 Markdown 报告 |

上表路径均遵循 `API_PREFIX`。实验字段：`kb_id`、`query`、`filters`、`top_k`、`top_n`、`rerank`、`mode`（search/chat）和 `orchestrator`（single/langgraph_multi）。其他 REST/MCP 请求不自动创建教学报告；需通过工作台或教学实验接口运行。
